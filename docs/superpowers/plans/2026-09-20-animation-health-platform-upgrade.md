# 奔跑修复、三颗心与分层路线改进方案

状态：主体已实施，自动化验收通过；真实浏览器与手机视觉验收仍待确认。方案最初记录的测试基线为 81 项，实施后为 91/91 通过。静态查看了新图集，但不能据此声称实际游戏画面已完全通过。

## 1. 已确认的问题

| 现象 | 当前证据 | 处理方向 |
| --- | --- | --- |
| 贝贝头顶出现鞋子残片 | 跑步图集按 240×320 分格，但源画面的首排鞋子越过了行边界；下一排源矩形会包含上排残片 | 单帧修图、共同锚点、留透明保护边后再装图集 |
| 跑步像快速抽动 | 每轮 96px；普通跑一轮 0.64 秒，冲刺一轮 0.40 秒。图集的肢体顺序也未形成完整、连续的左右脚交替 | 先修动作顺序，再校准步幅，不能仅降播放速度 |
| 孟培杰摆臂不自然 | 多帧近侧手臂持续在身前，部分姿势变化重复，肩肘轨迹跳变 | 明确左右肢体身份、交替支撑与对侧摆臂，逐帧审查 |
| 黄色方块还在 | `game.js` 的 patrol 分支完全使用 fillRect，没有接入高清图集 | 增补巡逻障碍高清素材和统一类型映射 |
| 平台仍混用老外观 | 静态平台走图集，collapse/motion 平台直接走旧方块绘制；塌陷提示也为方块 | 平台状态共用高清底材，状态变化单独表现 |
| 道路和长平台被压扁拉长 | 方形 256×256 素材被画到宽长、很薄的目标框；道路每段末端也把整幅素材挤窄 | 制作横向平铺材质与左/中/右端模块 |
| 箱子预警不完整 | constructionBox 高清绘制成功后立即 return，后面的旧预警绘制没有执行 | 将箱体和预警分开绘制，增加落点影子与落下阶段提示 |
| 没有生命系统 | 当前仅记录 damageCount，靠距离拉大/减速/回档惩罚；没有 hearts | 统一受伤入口，加入三颗心和无敌期 |
| 没有向下穿平台输入 | 输入只处理左右、冲刺和跳跃；落脚没有记录所站平台 ID | 增加 down + jump 与单向平台穿越状态 |
| 高路布局重复 | 五个区域共用同一组台阶与平台偏移；除桥区外高路缺少能量奖励 | 每区手写双层路线与奖励/风险组合 |

## 2. 本轮目标和边界

- 保持当前高清插画风、服装、脸型、发型与孟培杰的眼镜；人物维持当前放大后的约 66×88 视觉框。
- 地面接触线保持 y=510；普通移动和冲刺速度先不变，先修动作采样与路线内容。
- 保留原生 JS + Canvas 2D、无构建部署、固定步长时钟与 60/30 FPS 自适应。
- 保留 85% 追上窗口，新增垂直接触条件防止隔层获胜。
- 不加入屏幕震动或手机振动；受伤反馈采用短闪、心形变化、音效。

## 3. 人物动画修复（第一优先级）

1. 先处理单帧，再装配图集。不能把生成出的整页图直接缩为 960×960 就视为切片合格。
2. 每帧保留透明安全边，排除相邻帧的鞋、手、头发和细碎残像；装配时建立明确的源矩形与脚底锚点。缩放时需要额外边缘余量，避免线性采样取到隔壁帧。
3. 锁定一个完整左右脚周期：左触地→承重→经过→蹬离→腾空→右脚准备触地，再对称完成另一半。孟培杰不能用近似重复姿势凑满 12 格。
4. 肩膀到肘到手的运动连续，左腿向前时右臂向前；手不突然越过躯干换边。保留头部稳定和少量发梢/衣摆延迟。
5. 步幅先以 128px/完整周期试调，相比当前换帧节奏放慢 25%。普通跑约 0.85 秒/轮，冲刺约 0.53 秒/轮；这是待预览校准的起点，不作为未经验证的最终值。
6. 步幅同时与支撑脚在图内的后移距离匹配；不能为了慢腿造成脚在地上滑。预览页增加移动地面参照、支撑脚轨迹和两套候选步幅对比。
7. 起跳冻结地面相位；记录支撑侧，落地接对应承重帧。真正完成这一衔接，而不是仅保留一个跑步里程字段。
8. 审查跑、跳、落地、打滑、哭、倒地和拍打的全套姿势。孟培杰目前缺专用跳跃姿势，会回退到冻结的跑步帧，需要补齐。

验收：每格不串帧；慢放首尾连续；眼镜不消失；左右摆臂明确；以当前尺寸显示无头顶残脚；支撑脚的地面滑移目标≤4px。尺寸/透明通道测试之外必须逐帧和实际循环检查。

## 4. 向下 + 跳：主动离开高台

- 键盘：S/↓ 按住后按跳跃；手机：新增明确的“下落”触控按钮，触发同一动作。
- 平台数据区分 ground、solid、oneWay。只有标记为 oneWay 的高台能主动穿下；地面不允许穿透。
- 记录 groundedPlatformId。触发后仅暂时忽略当前平台（以及连接成同一平台的接缝片段），清除本次跳跃缓冲和土狼时间，给轻微向下速度。
- 角色完全低于该平台或安全超时后恢复碰撞；下一层平台仍正常接住，不允许一次指令穿到底。
- 下落动作不赠送额外空中跳跃；真正落地才重置正常二段跳次数。按住按键不重复穿层。
- 对移动台、塌陷台、平台边缘、两台接缝分别验证；移动台需先实现站立者随台移动。

## 5. 三颗心与陷阱规则

建议把“三颗心”定义为本轮生命，最大 3；新开一轮恢复 3，检查点不补满。

| 类别 | 建议效果 | 恢复方式 |
| --- | --- | --- |
| 香蕉、横风 | 打滑/减速，不额外扣心 | 状态结束恢复 |
| 巡逻车、尖刺、落箱、危险挡板 | 每次有效碰撞扣 1 心，短暂硬直 | 原地继续，约 1.2 秒受伤保护 |
| 深坑、致命落区 | 扣 1 心，回到最近安全检查点 | 清除过期输入和危险接触状态，提供约 1.5 秒保护 |
| 爱心拾取 | 补 1 心，上限 3 | 每个拾取点每轮仅可获取一次 |
| 心数归零 | 失败，贝贝坐下哭 | 重来/回主页面 |

- 所有伤害走同一个入口；同一物理步多个碰撞只结算一次，不沿用两套互不相通的伤害冷却。
- 冷却用于防连击，还需记录持续接触：同一个陷阱持续重叠不能每到冷却就再次扣心；离开再碰才是新碰撞。
- 普通受伤先取消额外“让孟培杰瞬移拉开”的惩罚，用短硬直自然拉开一点距离，避免扣血和大幅丢距离叠加。
- 跟丢与终点失败规则保留；回档时安排公平的追逐间距，不能刚复活就因距离直接输。
- 爱心不会因检查点回档重新刷新；已消耗的生命也不会随回档恢复。
- HUD 用三颗清晰爱心展示，受伤短闪，不做持续大面积闪烁。

## 6. 第一阶段和双层高台编排

把“第一阶段”按校园入口区处理，同时覆盖主旅程与独立校园章节。先制作这个完整样板，再把规则扩展到其它四区。

建议地面 y=510；第一层主要落在 y≈410，第二层主要落在 y≈310。通过中间踏板或弹簧连接，实际高度与水平间距必须用当前短跳/长跳/二段跳模拟验收，不能只靠 gap≤150 的静态规则。

| 段落 | 路线安排 | 学到/得到什么 |
| --- | --- | --- |
| 教学 | 开场保留短安全区；先给一个清晰单陷阱和低踏板 | 学会避险和识别可站表面 |
| 第一次选择 | 地面有短尖刺区；旁边提前提供上高台入口 | 学会选路；仍可精准跳过地面危险，不强制挨打 |
| 下落教学 | 一层高台放少量币，末端有安全下层落点 | 学会下 + 跳，失败成本低 |
| 第二层引入 | 阶梯/弹簧进入二层；短移动台+能量奖励 | 更高收益需要更主动的操作 |
| 加压 | 地面危险带与上层塌陷台组合，但预警不重叠遮挡 | 留在下层可能扣心，上层需快通过 |
| 喘息 | 连续安全路面、检查点，放一颗可见但非无条件送到手的爱心 | 恢复节奏与生命 |
| 小高潮 | 二层能量/篮球→避开预警落箱→下落返回一层 | 一段完整的跳、选路、取奖励、主动下台组合 |

- 每段危险之前必须有可见预警和可达入口；自动跑的最高速度下也有反应时间。
- 地面是较直观路线，一层提供捷径，二层是高风险高奖励。部分地面危险迫使玩家跳跃或上台，但不设置毫无预告的必扣心通道。
- 二层不铺满整关，保留上下切换、分支、汇合和安全落点；避免把原来一条平路复制成三条平路。
- 每个区域上层至少安排有价值的能量；整关爱心少量、固定位置、不可反复刷。
- 奖励放在能看见且能接近的位置，避免吸引玩家跳入不可恢复的落区。
- 孟培杰根据自身位置选择路线、起跳和下落；会在追上窗口前后进入可会合路段，不因两人永远隔层而无法获胜。

## 7. 道路、平台、道具整体美术统一

共同方向：清晰、偏日漫背景插画的校园世界；一致的光照方向、材质精细度和轮廓软硬程度，危险物与背景保持足够区分。

### 道路与平台

- 为道路制作独立的表面、路缘、侧壁和坑口端面。道路段落中间横向平铺，末端裁切，不把整个方图挤成薄条。
- 道路脚底接触边准确落在 y=510，明确表现坑口断面；装饰不跨过真实空洞造成“看起来有路却掉坑”。
- 平台采用左端+重复中段+右端，宽度变化不拉伸砖纹和支架；碰撞顶面与画面可站边一致。
- 平台厚度参考人物比例，补柔和接触阴影、端面与适量支撑结构，避免满屏悬浮厚砖。
- 普通台保持稳固外观；单向薄平台能看出可穿下；移动台有导轨/方向提示；塌陷台有裂纹和渐进松动；弹簧台有压缩状态。
- 五区同一世界、不同材质：校园暖灰石路，球场运动地面与看台边，银杏区浅石/木台，湖畔步道与施工台，天桥金属结构与铺装。光照随原背景变化，不引入不相干的城堡风格。
- 装饰栏杆放在角色后或道路前缘，保持前后层次，避免再次盖出双重栏杆和路灯虚影。

### 道具与陷阱

- 盘点所有运行时类型：篮球、香蕉、书包、挡板、巡逻车、落箱、塌陷台、弹簧、惊喜块、金币、能量、检查点、加速带、风区；新增尖刺和爱心也纳入同一资源表。
- 优先补齐巡逻车、塌陷/移动平台、加速带、预警标识；截图中的黄色方块必须完全退出正式绘制路径。
- 为所有素材登记源矩形、锚点、可见主体范围、目标尺寸与状态；不继续依赖未知类型兜底画书包。
- 统一高质量缩放、透明边缘和颜色；清理旧图集中可见的边界细线、杂色与残片。
- 效果类用平滑路径/渐变：风线、落点影子、触地灰尘、危险提示；高清不等于所有效果都需要大图片。
- 重要资源加载失败有明确重试，不能以旧像素替身掩盖失败；用覆盖清单检查每类物件正常、预警、触发、消失、恢复各状态。

## 8. 同次需要处理的隐藏问题

1. 隔层追上：当前只检查 x 间距≤56。增加合理的垂直重叠/接触条件，预留与画面拍打动作一致的水平容差。
2. AI 的虚拟地面：孟培杰在 y≥478 时直接落到固定地面，不检查地面坑。双层路线前需要改为实际平台落脚和自主避坑。
3. 塌陷配置不一致：platforms 里只明确列出 gate/ginkgo 的塌陷台，但 hazards 还有 court/bridge 对应项。改为一份实体数据派生碰撞和绘制，避免出现只有警告没有台子的“陷阱”。
4. 角色可见范围与伤害盒不一致：当前视觉框66×88、物理盒24×32。不要直接把物理盒放大破坏跳跃路线；分别校准脚部站立盒与躯干受伤盒，预览显示其边界后再定参数。
5. 检查点只看 x：分层后不能因为从远处上层飞过 x 就激活不安全落点；明确检查点区域、安全复活坐标和所处平台。
6. 输入失焦：当前未看到 blur/visibilitychange 时清空按键。新增下落输入时一起处理，避免切回页面仍持续冲刺或误穿台。
7. 移动台承载：当前有平台坐标变化函数，但没有玩家随站立平台位移的完整处理。先实现承载与接缝落脚，再增加移动台数量。

## 9. 实施顺序和验收

1. 修单帧、摆臂和步幅，清掉残片 → 逐帧/慢放/正常速度/DPR1与2检查。
2. 整理统一伤害、生命与单向平台 → 验证一次碰撞只扣一心，下落只穿当前层，心归零才触发对应失败。
3. 完成校园入口双层样板与 AI 实体落脚 → 模拟上下路线和复活安全，真人试玩校准密度。
4. 统一道路/平台/道具高清材质与所有状态 → 五区逐类覆盖截图，检查坑口、锚点、警告和缺资源处理。
5. 推广五区，调奖励与陷阱节奏 → 地面/一层/二层各有可通行路线，危险段有替代办法，高层奖励有吸引力。
6. 回归和发布 → node --test、路线模拟、桌面和手机视口实测；完成后按已有授权提交并推送，核对实际部署状态。

必须新增的行为检查：伤害去重与无敌、爱心上限及回档不刷心、归零失败、平台下落的接缝/移动/多层情况、AI避坑与独立选路、垂直分离不获胜、检查点安全落脚、失焦输入清理。

原81项测试保留有效行为，涉及新生命规则的旧预期按新规格更新，并扩充到91项；不把测试数量固定为验收目标。真人视觉验收必须覆盖普通跑、冲刺、换向、跳跃、滑倒、复活和结算，不能再以图集尺寸正确代替动作合格。

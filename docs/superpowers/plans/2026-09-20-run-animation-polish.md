# 人物奔跑动画与头顶提示优化方案

状态：已实施（2026-09-20）。角色动画、距离提示和预览页已更新；`node --test` 为 81/81 全绿。浏览器视觉验收受当前执行环境权限/连接问题阻断，线上 Pages 状态需在推送后另行确认。

## 1. 目标与范围

保留贝贝和孟培杰现在的服装、脸型、发型、孟培杰的眼镜，以及清晰的插画风格，让跑步具有连续的蹬地、腾空和落脚感；清理头顶像加载错误的距离数字。

保持原生 JavaScript + Canvas 2D、ES modules、无构建步骤；沿用固定步长 60/30 FPS 自适应。地图、速度数值、跳跃物理、85% 追上窗口与胜负规则不属于本次修改范围。按后续补充要求，人物视觉尺寸从约 60×80 调整为 66×88（放大约 10%）；地面基准仍为 y=510，并适当加宽可见路缘，不改变实际落脚线。

## 2. 已核实的问题

| 问题 | 当前证据 | 影响 |
| --- | --- | --- |
| 动作采样频率低 | `character-renderer.js` 每移动 46px 才切换下一张，循环仅 4 帧 | 普通速度 150px/s 时约 3.26 次换帧/秒；冲刺 240px/s 时约 5.22 次，60 FPS 渲染也无法补足缺失姿势 |
| 跑步姿势不完整 | 当前两张跑步图集的第 1、3 帧较接近，手臂姿势变化少；贝贝部分帧躯干朝向改变 | 看起来像图片轮播，左右腿没有完整交替，人物有跳变感 |
| 落地变形突然开始和结束 | `landTimerMs > 0` 时直接横向乘 1.1、纵向乘 0.88，结束时立即恢复 | 落地瞬间像缩小、弹回，缺少连续过渡 |
| 跑步相位包含空中位移 | 两个人的 `distanceTravelled` 都随水平移动累计 | 跳跃落地后可能直接切进不合适的跑步姿势 |
| 有未接入的摆臂腿函数 | `runner-pose.js` 提供肢体角度，但当前全身跑步图绘制没有调用它 | 修改这个函数不能直接修好当前跑步动画 |
| 孟培杰头顶出现 100px 等数字 | `game.js` 的 `drawGapLabel()` 绘制 `${gap}px`，主渲染每帧调用 | 是距离 HUD，不是图片加载失败；像调试信息，并增加角色附近的视觉干扰 |

数字经常接近 100 也有代码原因：追上窗口前存在 100px 的最小追逐间距约束，开窗时又会将较远的间距缩至最多 100px。本次处理其显示，不改变这些玩法规则。

## 3. 推荐方案

采用完整全身序列帧：先锁定 8 个核心姿势，再增加过渡帧形成 12 帧循环。相位由实际跑动距离驱动，一帧只画一张清晰角色图。

此方案能沿用当前绘制结构，不需要更换引擎。骨骼动画需要额外拆分胳膊、大腿、小腿、衣服与头发，并修补遮挡区域，暂不作为本次方案。不能把现有四张图片简单复制为十二张，也不能通过透明叠图或运动模糊掩盖缺帧。

### 3.1 清理角色上方信息

- 删除正式游戏中的 `drawGapLabel()` 调用和不再使用的函数。
- 保留顶部距离条，原有临近/危险反馈继续提供追逐信息。
- 孟培杰上方仅在需要时出现短时台词；结束后完全消失，不常驻像素数字。
- 台词框按实际角色视觉头顶留出空隙，限制在可见画布内，避免挡住脸、眼镜或前方落脚点。
- 动画调试数据只放在后续独立预览页，不增加正式游戏中的调试开关或技术说明。

### 3.2 十二帧动作编排

一轮表示左右腿各完成一次支撑与摆动。以下为动作意图，绘制时以自然的关节关系为准：

| 帧 | 动作 | 检查重点 |
| --- | --- | --- |
| 1 | 左脚触地 | 左脚成为支撑点，右臂向前；膝盖不锁死 |
| 2 | 左腿承重 | 膝盖弯曲，重心小幅下降 |
| 3 | 右腿向前经过 | 右膝向前，左脚开始向后蹬 |
| 4 | 左脚蹬离地面 | 身体前进，脚踝与脚尖完成蹬地 |
| 5 | 腾空 | 两脚离地，头部保持稳定 |
| 6 | 右脚准备落地 | 小腿展开，动作自然衔接下一帧 |
| 7 | 右脚触地 | 右脚支撑，左臂向前 |
| 8 | 右腿承重 | 与左腿承重对应，保留角色自身细微不对称 |
| 9 | 左腿向前经过 | 左膝向前，右脚向后蹬 |
| 10 | 右脚蹬离地面 | 蹬地姿势与下一次腾空相接 |
| 11 | 腾空 | 发梢、衣摆稍滞后于身体 |
| 12 | 左脚准备落地 | 与第 1 帧闭环，头、躯干和肢体不突跳 |

贝贝和孟培杰使用同一套基本运动原理，但各自维护独立相位。贝贝可稍轻快、摆臂积极；孟培杰可更放松。不能让两人共用动画计时或由贝贝的跳键改变孟培杰姿势。

### 3.3 步频与位移同步

将旧的“每帧走 46px”改为“每完成一整轮走多少距离”。初始建议整轮 96px，12 帧平均每帧对应 8px；最终结合脚在图内的运动幅度校准，预期调节范围约 90–110px/轮。

以 96px/轮估算：

| 水平速度 | 完成一轮时间 | 序列帧变化频率 |
| --- | --- | --- |
| 105px/s 回头移动 | 约 0.91 秒 | 约 13.1 帧/秒 |
| 136px/s 孟培杰巡航 | 约 0.71 秒 | 17 帧/秒 |
| 150px/s 普通跑 | 0.64 秒 | 18.75 帧/秒 |
| 190px/s 高路 | 约 0.51 秒 | 23.75 帧/秒 |
| 205px/s 孟培杰加速 | 约 0.47 秒 | 约 25.6 帧/秒 |
| 240px/s 冲刺 | 0.40 秒 | 30 帧/秒 |

这些是建议的动画参数，不修改游戏移动速度，也不代表每秒需要绘制多少次；渲染仍由现有时钟控制。

- 为每个角色保存独立的跑步相位，仅在跑步状态根据真实水平位移推进。
- 跳跃、打滑、倒地、哭泣切换到各自动作，不继续播放快速蹬腿。
- 回头时按移动距离绝对值推进相位并镜像朝向，不重置到第 1 帧。
- 速度变化不重置循环；不要额外平滑步频而造成脚部与实际地速脱节。前倾等表现参数可以平滑变化。
- 检查点回档和追逐规则造成的位置修正，不算作角色真正跑过的距离。
- 起跳记录当前支撑侧，落地优先接对应承重动作，再进入跑步循环。空中不累计地面跑步相位。

### 3.4 角色一致性、锚点与清晰度

- 两个人均使用独立的 12 帧图集，每帧 240×320，4 列×3 行，总图集 960×960；导出实际透明背景 PNG，不把棋盘格画进素材。
- 使用明确的 `{ x, y, w, h, originX, originY }` 帧描述，不靠图片总宽度推断帧数。
- 每帧沿用相同的角色比例和虚拟地面坐标；人物重心围绕相同水平基准运动，不逐帧按墨迹包围盒重新居中或拉伸。
- 支撑脚触地帧贴合地面；腾空帧允许脚自然离地。不能为了“脚底对齐”把所有帧都压回地面。
- 保持脸部、眼镜、发色、鞋子、衣服配色和细节一致。手脚不得越过帧边界，帧间保留足够透明余量。
- 保持身体原有大小；蹲低、腾空和落地造成的姿态变化通过关节表达，不强行把不同姿势的轮廓都拉到同样高度。
- 保持高质量图像缩放；正常跑步不用拖影、全身透明叠加或动态模糊。
- 初期资源目标：两个人的新跑步图集合计尽量控制在 2MB 内；两张 960×960 RGBA 图解码占用约 7.4MB，需纳入手机实际内存检查。质量不达标时优先调整压缩与透明边缘，不随意缩小脸部细节。

### 3.5 落地与附属动作

- 将突然的 0.88 倍高度压缩改为连续恢复曲线，建议仅保留约 2%–4% 的轻微弹性，持续约 80–120ms。
- 有专门承重帧时优先用姿势表达重量，避免再次叠加大幅全身缩放。
- 头部小幅起伏、躯干适度前倾；不增加第二套独立高频上下抖动。
- 头发和衣摆的跟随动作尽量画进序列帧，幅度不能影响识别或显得衣服换形。
- 脚边灰尘改为触地事件触发，短暂出现；不再仅凭跑步帧编号奇偶持续显示方块。
- 跑步到跳跃、落地到跑步使用匹配姿势接续，不通过两张全身图交叉淡入淡出。

## 4. 实施顺序与交付物

### 阶段 A：清理提示并建立预览

修改 `game.js` 头顶标签绘制，建立独立的动画预览页，展示原版和新版对比。预览页提供速度选择、左右朝向、逐帧、慢放、脚底线和重心参考线；这些参考线不进入游戏界面。

验收：正常游玩、上下平台和结算时都不再出现头顶 `100px`；顶部距离条继续工作。预览可以独立打开检查循环首尾。

### 阶段 B：锁定关键姿势与素材

以目前两人的外观作为参考，先完成贝贝的 8 个关键姿势并检查左右腿轮换，再补到 12 帧；孟培杰按同一流程制作。需要修正不一致的脸或服装时先修素材，不能靠运行时遮盖。

交付：两张 12 帧图集、对应帧描述、预览页中的慢速循环。图像生成只能辅助出素材，不能保证一次生成的多帧人物完全一致；裁切、透明边缘和逐帧一致性检查是必要工序。

验收：无重复凑数帧、残肢、衣服变色、身体视角突然改变或眼镜消失；第 12→1 帧自然闭环。

### 阶段 C：接入距离驱动的独立相位

修改 `character-renderer.js` 的帧选择及图集绘制；在 `game-logic.js` 与 `pursuer-ai.js` 中维护各自的有效跑动相位，复用现有状态更新方式。现有 `runner-pose.js` 不承担新全身帧的驱动，避免修改无效路径。

验收：相同实际跑动距离对应相同循环位置；两人速度不同时步频各自变化；空中、倒地和位置回档不会产生异常跑步推进；切换冲刺和回头不重新从第 1 帧开始。

### 阶段 D：处理落地、跳跃与反馈

完成支撑腿匹配、轻微落地恢复、触地灰尘；检查普通跑、高路加速、冲刺、受伤、打滑、起跳、二段跳、落地、转向与结算之间的衔接。

验收：没有落地突然缩小或弹回，没有在空中提前切回跑步，没有切回旧衣服或旧人物。

### 阶段 E：加载、测试与发布

两套图集通过加载门控后才进入游戏；加载失败应在现有加载区域提示重试，不能无限停在“角色加载中”，也不能回退成旧方块人物。复用当前资源结构，只增加处理新角色图集所需的逻辑。

更新实际受影响的模块/资源缓存版本号，完成本地验收后提交。若发布本次修改，推送后分别确认远端源码和 Pages 构建/实际页面，不以 Git 推送成功替代线上验收。

## 5. 自动化检查

沿用 `node --test`；当前基线为 78 项。修改编码了“四帧、46px/帧”的旧测试，使其验证新循环行为，不为了保持原数字而保留旧预期。

新增或调整的重点行为检查：

- 12 帧循环首尾、边界以及大位移跨帧正确。
- 不同更新时间切分下，同一有效地面位移得到相同相位。
- 两人的相位独立；空中、倒地、回档不错误计入跑步里程。
- 跳跃和落地切换使用正确状态与支撑侧；转向不清零相位。
- 图集源矩形在图片范围内；素材未加载时不会绘制旧方块替身。
- 加载失败和重试可恢复；结算后不继续触发落地灰尘。

执行 `node tools/level-bot.mjs` 回归玩法，确认纯动画改动没有改变路线可达性、胜负与追逐节奏。头顶文字的视觉清理以浏览器检查为主，不新增只检查源码字符串的脆弱测试。

## 6. 视觉验收与成功标准

桌面与手机视口分别检查 DPR 1/2、60/30 FPS 模式；手机实际性能和触控需实机检查，桌面缩窄视口不能完全替代。

- 正常速度不再出现约每 0.3 秒才换一次姿势的停顿感。
- 双臂与双腿交替明确，脚有承重、蹬地和腾空过程。
- 慢放检查单次支撑期内，脚相对地面的滑移目标不超过约 4 个世界像素；若超出，调整图内脚部轨迹与循环距离，而不是添加模糊。
- 稳定站立基准与触地帧基线误差目标不超过 1 源像素；腾空高度不按此规则强制对齐。
- 脸、衣服、眼镜与角色比例稳定，动画循环无横向抖动、切边或残影。
- 跑、跳、落地和转向连续；角色保持原来的视觉大小和物理位置关系。
- 孟培杰头顶无 `px` 数字，台词不遮挡角色脸部。
- 新图集不会在首次开跑时造成明显卡顿；性能检查记录实际测试设备与观察结果，不预先承诺所有手机都稳定 60 FPS。
- 若浏览器或手机验收受环境阻断，交付时明确列出未验证部分，不以测试全绿声称视觉已达标。

# 《等等贝贝吧》第二版设计

## 目标与边界

把现有连续追赶地图升级为一张约 5–8 分钟的原创横版跑酷地图：五个有明显风景和玩法差异的区域连续相接。玩家操控董贝贝自动向前跑、跳跃和二段跳，在障碍与互动道具中追赶孟培杰。

项目继续使用原生 HTML、CSS、Canvas 和 ES 模块，保持 GitHub Pages 直接发布能力。只参考许可明确的开源项目的模块划分与玩法节奏；不复制代码、角色、素材、音效或关卡。

## 世界与关卡数据

关卡改为由 `level-data.js` 的区域数据生成，不再以相同的 1,000 像素段重复铺设。每个区域定义长度、调色板、远景/中景/近景、地面与平台、检查点、道具、陷阱和事件密度。

| 路程 | 区域 | 风景 | 主要玩法 |
| --- | --- | --- | --- |
| 0–20% | 校园入口 | 校门、公告栏、花坛、晨光 | 低矮平台、书包、教学用断桥 |
| 20–40% | 篮球场 | 球架、看台、操场树影 | 自动踢篮球、长平台与跳台 |
| 40–60% | 银杏林路 | 银杏、长椅、落叶、午后光影 | 香蕉皮滑倒、连续高低台 |
| 60–80% | 湖畔施工区 | 栈桥、吊灯、湖面、施工围栏 | 移动平台、摆动吊桥、较窄落脚点 |
| 80–100% | 黄昏天桥 | 城市剪影、桥灯、晚霞 | 风力区域、组合跳跃、终点追上窗口 |

每区至少有一种独有前景物与一种独有交互，不得只通过改色重复树、地面和平台。相机采用三层视差（远景慢、中景中、前景快），世界实体统一在相机坐标系中绘制。

## 实体与互动规则

`entities.js` 定义通用矩形碰撞实体；`game-logic.js` 只更新状态，不绘制。

- 贝贝：自动向右跑；按左键时减速并完整朝左转向。跑步时双臂和双腿反相摆动，跳跃、滑倒、哭泣和胜利动作都有独立姿态。
- 香蕉皮：碰到后进入短暂 `slipping` 状态，减速、失去跳跃能力并增加一次失误记录；不会直接判失败。
- 书包、围栏和坑洞：分别造成碰撞减速、强制绕跳和掉落回检查点。
- 篮球：贝贝触碰后立即向当前前方滚动/飞行；命中孟培杰时由一次可测试的随机判定决定 `slowed` 或 `downed`。减速缩短他的速度优势；倒地会使其停顿并显著缩短距离。篮球不会伤害或描绘暴力细节。
- 跳台、移动台、吊桥：只在各自主题区出现，用于制造不同跳跃节奏。

## 孟培杰独立 AI 与追上判定

孟培杰维护自己的 `x`、`velocity`、`facing`、`pose`、`mode` 和状态计时器，不再根据贝贝的坐标或动作直接渲染。

| AI 状态 | 触发 | 行为 |
| --- | --- | --- |
| `cruise` | 默认 | 以基础速度跑动，保持领先距离 |
| `evade` | 贝贝进入近距离范围 | 短时加速，之后冷却，避免一直无法追上 |
| `slowed` | 被篮球命中 | 降速约 2 秒 |
| `downed` | 篮球命中判定为摔倒 | 停顿后恢复，显示独立倒地姿态 |

从路程达到 70% 开始，只要二人进入“追上范围”，每隔固定的追上判定间隔执行一次机会判定。基础成功率为 18%；无掉落、无滑倒和无障碍碰撞的无失误跑法增加 16%；孟培杰处于减速状态增加 18%；倒地状态增加 45%。成功即进入现有轻拍、台词和胜利结算流程。孟培杰的 `evade` 冷却保证每次靠近都存在真实机会，而不是自动必败。

随机数由逻辑层注入或以可替换函数提供，自动化测试可指定固定结果；正常游玩使用 `Math.random()`。

## 模块边界

| 文件 | 职责 |
| --- | --- |
| `level-data.js` | 五个区域及其实体配置，不含运行时状态 |
| `game-logic.js` | 物理、碰撞、失误、道具、追上概率和胜负状态 |
| `pursuer-ai.js` | 孟培杰状态机与速度决策 |
| `camera.js` | 平滑相机和视差偏移计算 |
| `game.js` | 输入、动画帧、Canvas 调度和 HTML 对话框 |
| `scene-renderer.js` | 主题背景、平台和前景绘制 |
| `character-renderer.js` | 贝贝与孟培杰的独立动作、转向和表情绘制 |

现有公开文案、失败坐地哭、胜利台词“没心眼，不等我”、主页面和 GitHub Pages 地址保持不变。

## 验收与测试

- 五个区域在截图和运行时都可由风景、前景物和互动规则区分。
- 镜头持续跟随贝贝，视差方向正确；贝贝向左时头、躯干、手臂和腿一起转向。
- 孟培杰的跑步、加速、减速和倒地不复制贝贝动作。
- 自动踢球、球命中、香蕉皮滑倒、移动平台和掉坑均有单元测试。
- 用固定随机数验证：70% 前不能概率追上；70% 后接近时可成功；失误和篮球命中改变成功率。
- `npm test` 全绿；桌面和 390px 手机视口浏览器检查没有脚本错误、失败请求或溢出。
- 只推送源码和所需原创素材；`docs/` 设计文档与实现同步提交。
